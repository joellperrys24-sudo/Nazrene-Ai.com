Accessibility Statement

Last updated: 2026 · Nazrene AI, London, United Kingdom

In short. This website has been built to be usable by keyboard, screen reader and voice control, and to respect your system's reduced-motion preference. We aim to meet WCAG 2.2 Level AA. If you hit a barrier, tell us and we will fix it.

1. Our commitment

Nazrene AI wants everyone to be able to use this website, whatever device or assistive technology they rely on. Accessibility is part of how we build, not something added afterwards — and it matters commercially as well as ethically, because a site that excludes people excludes customers.

2. The standard we aim to meet

We aim to conform to the Web Content Accessibility Guidelines (WCAG) 2.2, Level AA, published by the World Wide Web Consortium (W3C). These guidelines are built around four principles — content should be perceivable, operable, understandable and robust.

This site is not currently subject to the Public Sector Bodies (Websites and Mobile Applications) Accessibility Regulations 2018, because Nazrene AI is not a public sector body. We follow the same standard voluntarily.

3. What we have done

Structure and navigation

  • Semantic HTML landmarks (header, nav, main, footer, section) so assistive technology can navigate by region.
  • A single, clear h1 on each page, with a logical heading hierarchy beneath it and no skipped levels.
  • A "skip to main content" link as the first focusable element on the home page.
  • Descriptive page titles that identify the page before the site name.
  • The language of every page is declared as British English (lang="en-GB") so screen readers use the correct pronunciation.

Keyboard access

  • Every interactive element — links, buttons, form fields, the mobile menu, the FAQ accordion — is reachable and operable using the keyboard alone.
  • A visible focus indicator appears on every focusable element, with sufficient contrast against the background.
  • The mobile menu can be closed with the Escape key, and focus returns to the button that opened it.
  • The FAQ accordion supports Enter, Space, Arrow Up, Arrow Down, Home and End.
  • No keyboard trap exists anywhere on the site.

Colour and contrast

  • Body text and headings meet or exceed a 4.5:1 contrast ratio against their backgrounds.
  • Interface components and focus indicators meet the 3:1 non-text contrast requirement.
  • Colour is never the only means of conveying information — status indicators are paired with text labels.

Forms

  • Every input has a programmatically associated label, so screen readers announce what the field is for.
  • Required fields are identified in text, not by colour alone.
  • Validation errors are announced to assistive technology using ARIA live regions, and describe how to fix the problem in plain language.
  • Error messages are linked to the field they relate to, and focus moves to the first field needing attention.
  • Submission success and failure states are announced, not merely displayed.
  • Autocomplete attributes are set on personal detail fields to support browser and assistive-technology autofill.

Motion and animation

  • The site respects the prefers-reduced-motion setting. When you have reduced motion enabled, the hero video does not crossfade, scroll reveals resolve immediately, the marquee stops, and all decorative animation is suppressed.
  • No content flashes more than three times per second.
  • No animation is required to read or use any part of the site.

Media

  • Background video is muted, loops without sound, and plays inline. It carries no information that is not also present in the surrounding text.
  • Decorative graphics are hidden from assistive technology with aria-hidden.
  • Informative icons that accompany text are marked as decorative, because the text already conveys the meaning.

Responsiveness and zoom

  • The layout adapts to desktop, tablet and mobile viewports.
  • Content remains usable when text is enlarged, and the layout reflows without horizontal scrolling at 320 CSS pixels wide.
  • Text is set in relative units so browser font-size preferences are respected.

4. Known limitations

We would rather tell you what is not yet perfect than claim otherwise:

  • Background video. The hero uses decorative background footage. It carries no information, but it does consume bandwidth. If you prefer no video at all, the site is fully usable without it, and we can provide a video-free version on request.
  • Third-party links. WhatsApp and LinkedIn are external services whose own accessibility we do not control.
  • Google Fonts. Typefaces are loaded from Google's servers. This is a normal third-party request but does mean an external dependency.
  • Automated and manual testing. This site has been built and reviewed against WCAG 2.2 AA criteria, but has not yet been audited by an independent accessibility specialist or tested with the full range of assistive technologies in real-world conditions. We intend to commission a formal audit as the business grows.

6. Tell us about a problem

If you find something on this website that you cannot use, or that is harder to use than it should be, please tell us. Include the page, what you were trying to do, and what happened.

We aim to acknowledge accessibility reports within 5 working days, and to give you a clear answer on what we will do. Where a fix is straightforward we will make it promptly. Where it is not, we will tell you honestly and offer you a workaround in the meantime.

7. How this statement was prepared

This statement was prepared by evaluating the website against WCAG 2.2 Level AA success criteria, including structural review, keyboard-only navigation, contrast measurement, form behaviour and reduced-motion behaviour. It was last reviewed on the date shown at the top of this page.

We will review it whenever the site changes significantly, and at least annually.

A note on this document. This statement describes the accessibility measures currently built into this website, based on our own evaluation. It has not been independently audited. Where we say "we aim to" or "we intend to", that reflects work still outstanding rather than work completed.
